# 使用现成 FTP 服务器软件搭建 FTP 笔记

## 一、核心认知

> **实际开发中，搭建 FTP 服务器一般由后端程序员负责，不需要前端/游戏客户端来完成。**

标准协作流程：

1. **后端**搭建 FTP 服务器 → 配置好地址、端口、账号、密码；
2. **后端**把连接信息提供给前端（如：`ftp://10.100.209.199:21`、用户名、密码）；
3. **前端**拿到信息后，用 FTP 客户端（FileZilla / Windows 资源管理器 / 代码）**访问即可**，不参与服务器搭建。

---

## 二、搭建方式：使用现成的 FTP 服务器软件

不用自己从零写服务端，直接下载安装成熟的 FTP 软件即可。常见选择：

| 软件 | 说明 |
|------|------|
| **Serv-U** | 经典 FTP 服务器软件，图形化配置，企业常用 |
| FileZilla Server | 开源免费，配置简单 |
| IIS 自带 FTP | Windows 自带，需在“启用或关闭 Windows 功能”中开启 |

> 笔记以 **Serv-U** 为例，其他软件流程大同小异。

---

## 三、Serv-U 搭建步骤（三步走）

### 1. 创建域 → 一路“下一步”

- 安装并启动 Serv-U；
- 在“域”上右键 → “新建域” → **直接不停点“下一步”**，使用默认配置即可完成域的创建；
- 域的作用：相当于一个 FTP 站点的“总入口”，绑定 IP、端口（默认 21）、根目录。

### 2. 使用单向加密

- 在域设置的“安全性 / 加密”选项里，加密方式选择 **单向加密（One-Way Encryption）**；
- 含义：密码以哈希形式存储，**只可验证、不可还原**；
- 对比“双向加密”：双向需要额外的密钥交换，配置更复杂，一般搭建内网/测试 FTP 用单向加密即可。

### 3. 创建两类账号

根据用途，分别创建两种账号：

| 账号类型 | 用途 | 权限建议 |
|---------|------|---------|
| **上传账号**（有用户名 + 密码） | 允许上传文件、修改文件 | 读写权限，需账号密码登录 |
| **下载匿名账号**（anonymous） | 允许任何人下载文件 | **只读权限**，允许匿名访问 |

> **安全原则**：上传必须鉴权（防止乱传），下载可开放（方便分发资源）；两类账号职责分离，互不越权。

---

## 四、搭建完成后前端如何使用

后端把信息给你后，前端**不在浏览器里输入 `ftp://`**（新版浏览器已不支持），而是用：

| 方式 | 说明 |
|------|------|
| **Windows 资源管理器** | 地址栏输入 `ftp://IP:端口`，像操作本地文件夹一样上传下载 |
| **FileZilla / WinSCP** | 填主机、端口、用户名、密码，功能最完整 |
| **代码调用** | C# 用 `FtpWebRequest`、Unity 用 `UnityWebRequest`（配合 FTP 插件）实现自动上传/下载 |

---

## 五、易错点小结

| 易错点 | 说明 |
|--------|------|
| 让前端去搭 FTP | 职责错位，搭建是后端的活，前端只负责“访问” |
| 浏览器输 `ftp://` | Chrome/Edge/Firefox 新版已移除 FTP 支持，页面无反应 |
| 上传账号开放匿名 | 安全隐患，任何人都能往里传文件 |
| 下载账号给写权限 | 同上，应严格只读 |
| 忘记防火墙放行 21 端口 | 局域网其他机器连不上 |
| 被动模式端口未放行 | 能登录但列目录/传输卡住，需在服务端配置被动端口范围并在防火墙放行 |

---

## 六、一句话总结

> **FTP 服务器由后端用 Serv-U 等现成软件搭建（建域 → 单向加密 → 建上传账号 + 匿名下载账号），前端拿到后端给的地址和账号后，用资源管理器或 FTP 客户端访问即可，不需要自己搭、也不要用浏览器打开 `ftp://`。**
