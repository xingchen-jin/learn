# 客户端热更新路径优化 笔记（针对更新内容）

本次更新是整个热更新系统的“收官之战”，核心解决了**多平台（PC、Android、iOS）下的路径适配问题**。课前版本的代码在 PC 编辑器下可以跑通，但直接打包到移动端就会因为**路径前缀缺失或多余**而报错。

---

## 一、核心知识点：多路测试（条件编译）

在编写跨平台代码时，不同平台的行为不同，我们使用 `#if ... #elif ... #else ... #endif` 来控制**哪些代码在哪个平台参与编译**。

```csharp
string pInfo = 
#if UNITY_IOS
    "IOS";
#elif UNITY_ANDROID
    "Android";
#else
    "PC";
#endif
```

### ⚠️ 致命语法坑
1. **必须要有 `#endif` 收尾**！漏写会导致整个脚本后面的代码无法编译，Unity 会报一堆莫名其妙的错误（视频中演示了漏写 `#endif` 导致的报错）。
2. 条件编译指令**不能加分号**（如 `#if UNITY_IOS;` 是错的）。
3. 平台宏（如 `UNITY_IOS`、`UNITY_ANDROID`）由 Unity 在打包时自动定义，无需手动声明。

## 二、更新点一：远端下载路径按平台区分

### 课前（硬编码）
```csharp
// 无论在什么平台，都去下载 PC 文件夹下的资源
new Uri("ftp://10.100.209.199/AB/PC/" + fileName);
```

### 课后（动态获取平台 + 提取服务器 IP）
1. 将服务器 IP 提取为全局变量，避免多处硬编码：
   ```csharp
   private string serverIP = "ftp://10.100.209.199";
   ```
2. 在 `DownLoadFile` 方法中，利用条件编译拿到当前平台名：
   ```csharp
   string pInfo = 
   #if UNITY_IOS
       "IOS";
   #elif UNITY_ANDROID
       "Android";
   #else
       "PC";
   #endif
   ```
3. 拼接下载路径：
   ```csharp
   new Uri(serverIP + "/AB/" + pInfo + "/" + fileName);
   ```

> **注意**：服务端必须根据平台建立相应的文件夹（如 `/AB/PC/`、`/AB/Android/`、`/AB/IOS/`），否则会提示找不到文件。

## 三、更新点二：本地文件读取的前缀处理（重灾区）

移动端对本地路径的读取有严格的前缀要求。**前缀加不加，取决于“哪个路径” + “哪种读取方式” + “哪个平台”**。

### 1. `File.ReadAllText`（流读取） -> **绝对不要加 `file:///`**
*   **场景**：下载完 `_TMP.txt` 后，读取远端对比文件内容。
*   **规则**：`File.ReadAllText` 是系统层面的文件流读取，直接传路径即可。如果加了 `file:///`，它会以为你要找一个名字叫 `file:///` 的文件夹，直接报错找不到文件。

### 2. `UnityWebRequest` 读取 `PersistentDataPath` -> **必须加 `file:///`**
*   **场景**：读取本地已更新过的 `ABCompareInfo.txt`。
*   **规则**：无论 PC、Android 还是 iOS，`UnityWebRequest.Get()` 都必须带前缀。
*   **代码**：
    ```csharp
    StartCoroutine(GetLocalABCompareFileInfo("file:///" + Application.persistentDataPath + "/ABCompareInfo.txt", overCallback));
    ```

### 3. `UnityWebRequest` 读取 `StreamingAssetsPath` -> **分平台**
*   **场景**：首次运行读取安装包内置的 `ABCompareInfo.txt`。
*   **Android 平台**：文件在 APK 压缩包内，系统会自动添加 `jar:file:///` 前缀，**代码里直接传路径即可**，不要手动加。
*   **PC / iOS 平台**：和普通文件系统一样，**必须手动加 `file:///`**。
*   **代码**：
    ```csharp
    string path = 
    #if UNITY_ANDROID
        Application.streamingAssetsPath + "/ABCompareInfo.txt";  // 安卓不加
    #else
        "file:///" + Application.streamingAssetsPath + "/ABCompareInfo.txt"; // PC/iOS加
    #endif
    StartCoroutine(GetLocalABCompareFileInfo(path, overCallback));
    ```

### 4. `FtpWebRequest` + `FileStream` 写入本地 -> **不用加**
*   **场景**：下载 AB 包或对比文件并保存到本地。
*   **规则**：因为是直接通过 `File.Create(localPath)` 创建文件流写入，属于标准的 IO 操作，不需要任何 URL 前缀。

## 四、踩坑复盘（视频中的真实报错）

1.  **缺了 `#endif`**
    *   **现象**：Unity 报错说 `#if` 没有匹配的 `#endif`，整个脚本编译失败。
    *   **解决**：在 `#else` 分支的末尾补上 `#endif`。
2.  **`File.ReadAllText` 多加了 `file:///`**
    *   **现象**：解析远端对比文件时报错，提示找不到路径。
    *   **解决**：删掉 `File.ReadAllText` 里面的 `file:///` 前缀，直接传 `Application.persistentDataPath + "/ABCompareInfo_TMP.txt"`。

---

## 五、一句话总结

> **本次更新解决了“跨平台热更新”的最后一公里问题。** 核心通过 `#if / #elif / #else / #endif` 条件编译，动态获取平台名以拼接远端 FTP 路径（PC/Android/IOS），并对本地文件读取做了精细化的前缀管理：`File.ReadAllText` 绝对不加前缀，`UnityWebRequest` 读可写目录必加 `file:///`，读 `StreamingAssets` 则需区分 Android 与其他平台。
