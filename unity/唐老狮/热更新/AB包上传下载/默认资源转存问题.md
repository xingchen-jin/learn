## 默认资源转存问题

### 1. 什么是"默认资源"

打包时除了把 AB 包和 `ABCompareInfo.txt` 传到 FTP，还要把**一份初始版本**放进 `Assets/StreamingAssets/`（见《编辑器功能-设置默认资源》）。这份随包体发布的资源就是"默认资源"，玩家第一次安装、还没联网更新时用的就是它。

于是运行时有**两套资源目录**：

| 目录                                | 放什么      | 能不能写 | Android 上                                                                              |
| --------------------------------- | -------- | ---- | -------------------------------------------------------------------------------------- |
| `Application.streamingAssetsPath` | 默认资源（首包） | 只读   | 在 APK 内部，形如 `jar:file:///.../base.apk!/assets`，**`File` API 用不了**，只能 `UnityWebRequest` |
| `Application.persistentDataPath`  | 热更新下载的资源 | 可读写  | 普通沙盒目录，`File` API 正常                                                                   |

热更新的目标是：让"本地资源"最终只有一份、而且是最新的。可默认资源在只读目录里，就产生了"转存"的问题。

### 2. "转存"是什么，为什么难

两种思路：

1. **物理转存**：第一次启动时，把 `StreamingAssets` 里的默认资源（对比文件 + AB 包）复制到 `persistentDataPath`，之后所有逻辑只认 `persistentDataPath`；
2. **逻辑转存（按优先级读）**：不复制，读的时候先看 `persistentDataPath`，没有再回退到 `StreamingAssets`。

物理转存的代价：

| 问题 | 说明 |
|------|------|
| Android 读不了源文件 | `StreamingAssets` 在 APK 里，`File.Copy` / `File.ReadAllBytes` 全部失败，只能 `UnityWebRequest` 读出字节再 `File.WriteAllBytes` 写出去 |
| 首次启动变慢 | 要把全部默认 AB 包拷一遍，包越大越慢，玩家要干等 |
| 占双份空间 | 转存后同一批资源在设备上存了两份 |
| 需要"已转存"标记 | 否则每次启动都重复复制，而标记文件本身也可能写坏 |

所以**本课代码选方案 2**：不物理转存，`GetLocalABCompareFileInfo` 里按 `persistentDataPath → StreamingAssets` 的顺序找对比文件（见第三节）。

> ⚠️ 关键配套：AB 包的加载也必须用同样的优先级。否则会出现"对比用的是新对比文件、加载用的却是 StreamingAssets 里的旧包"的错位。
>
> 本课只解决了"读"的回退；真正更新下来的 AB 包始终写进 `persistentDataPath`，`StreamingAssets` 里的默认资源保持出厂状态，不会被改坏。

### 3. 真正要解决的问题：直接下载会覆盖本地对比文件

第一版 `DownLoadCompareFile()` 是这么写的：

```csharp
DownLoadFile("ABCompareInfo.txt", Application.persistentDataPath + "/");
string compareInfo = File.ReadAllText(Application.persistentDataPath + "/ABCompareInfo.txt");
```

远端对比文件**直接覆盖**了本地对比文件。可"对比"本身就需要两份：远端一份、本地一份。本地这份被覆盖，就没得比了。

课程里对这段的注释（原文）：

> 原来的方法由于会覆盖本地的对比文件，所以不具备对比功能
> 也许会想，可以把本地的读取到内存再覆盖，但是这样做如果后续AB包下载失败，需要重下，没有正确的本地对比文件
> 所以有两个方法解决
> 1，下载对比文件到临时文件，待AB包下载完毕再把临时文件覆盖至本地对比文件
> 2，下载对比文件到内存，直接读取数据流，用字符串保存，改的代码多，好处是不需要额外的临时文件

为什么"先读到内存再覆盖"也不行？

- 内存里的本地信息只够**这一次**对比用；
- 一旦 AB 包下载失败（断网、中途关游戏），下次启动还得重下，可磁盘上的"本地对比文件"已经被换成远端版本了 —— **"哪些包需要下载"的依据丢了**，只能全量重下或者判断失误。

两种方案：

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| ① 临时文件（本课采用） | 远端对比文件存成 `ABCompareInfo_TMP.txt`，AB 包全部下载成功后再覆盖 `ABCompareInfo.txt` | 改动小；中途失败时本地对比文件仍是旧的，下次启动能正确对比 | 多一个临时文件，要管好"什么时候覆盖" |
| ② 下载到内存 | 不落盘，直接把响应流读成 `string` 拿去解析 | 干净，不产生临时文件 | 要改下载逻辑（`DownLoadFile` 不再写文件），改动大；重试时也要重新走一遍 |

> 一句话：**"本地对比文件"是判断差量的唯一依据，在整个更新成功之前必须保持原样。**

### 4. 本版代码的落地

- `DownLoadCompareFile` 下载到 `persistentDataPath/ABCompareInfo_TMP.txt`；
- `CheckUpdate` 读的也是这个 TMP 文件；
- AB 包全部下载成功后，再把远端内容写进正式的 `ABCompareInfo.txt`（第三版已实现，见《资源更新删除》）。

```csharp
// 下载：远端文件 → 本地临时文件
isOver = DownLoadFile("ABCompareInfo.txt", localPath + "ABCompareInfo_TMP.txt");

// 解析：读的是 TMP，不是正式文件
string remoteInfo = File.ReadAllText(Application.persistentDataPath + "/ABCompareInfo_TMP.txt");
GetRemoteABCompareFileInfo(remoteInfo, _remoteABInfoDic);
```

> 细节：`DownLoadFile` 的 `localPath` 语义变了 —— 第一版是"目录"（末尾带 `/`，内部再拼 `fileName`），第二版是**完整文件路径**（内部直接 `File.Create(localPath)`）。所以调用处要自己把文件名拼进去。

## 获取远端对比文件信息

### 1. 对外接口变化（第一版 → 第二版）

| 成员 | 第一版 | 第二版 | 说明 |
|------|--------|--------|------|
| `ABInfo` | `private class` | `public class` | 被 public 方法的参数暴露，不改会报 CS0051（可访问性不一致） |
| 对比文件字典 | `_abInfoDic` | `_remoteABInfoDic` + `_localABInfoDic` | 远端、本地各存一份才能对比 |
| 下载对比文件 | `DownLoadCompareFile()`，内部"下载 + 读取 + 解析"一条龙 | `DownLoadCompareFile(UnityAction<bool>)`，`async`，只负责下载，带 5 次重试 | 下载与解析解耦 |
| 解析 | 混在下载方法里 | `GetRemoteABCompareFileInfo(string, Dictionary<string, ABInfo>)` | 传入字符串和字典，远端/本地共用 |
| 总入口 | 无 | `CheckUpdate(overCallBack, updateInfoCallBack)` | 串起"远端 → 本地 → 下载" |
| 下载 AB 包 | 无 | `DownLoadABFile(overCallback, updatePro)` | 第二版新增；第三版收回 `private` |
| `DownLoadFile` | `void`，失败只打日志 | `bool`，失败返回 `false` | 重试要靠返回值判断成败 |
| `DownLoadFile` 的 `localPath` | 目录 | 完整文件路径 | 见上一节 |
| `==` / `!=` | `a.md5 == b.md5`，有 null 就 NRE | 先 `ReferenceEquals`、再 `is null` 判空 | 更安全 |

> 注：`ABInfo` 这一处访问修饰符确实变了（`private` → `public`），不是笔误。因为 `GetRemoteABCompareFileInfo` 是 public 方法，参数里出现了 `Dictionary<string, ABInfo>`；public 方法不能暴露 private 类型，编译器会直接报 CS0051。这是"接口一公开，内部的类型就跟着公开"的典型例子。

`==` 的完整写法：

```csharp
public static bool operator ==(ABInfo a, ABInfo b)
{
    if (ReferenceEquals(a, b)) return true;   // 同一个对象（也覆盖两个都 null）
    if (a is null || b is null) return false; // 一个 null 一个不 null
    return a.md5 == b.md5;
}
public static bool operator !=(ABInfo a, ABInfo b) => !(a == b);
```

> 重载了 `==` 却没重写 `Equals` / `GetHashCode`，编译器会给 CS0660 / CS0661 警告。放进 `Dictionary`/`HashSet` 时行为可能不对，实际项目要补上。

### 2. 总入口：CheckUpdate

调用方（`Main.cs`）：

```csharp
ABUpdateMgr.Instance.CheckUpdate(
    isSuccess => { /* 更新是否成功，成功就隐藏进度条 */ },
    updateInfo => { print(updateInfo); /* 给玩家看的进度文字 */ }
);
```

```csharp
public void CheckUpdate(UnityAction<bool> overCallBack, UnityAction<string> updateInfoCallBack)
{
    updateInfoCallBack("开始更新资源");
    DownLoadCompareFile((isOver) =>
    {
        if (!isOver) { overCallBack(false); return; }   // 下载失败直接结束

        updateInfoCallBack("对比文件下载结束");
        string remoteInfo = File.ReadAllText(Application.persistentDataPath + "/ABCompareInfo_TMP.txt");
        GetRemoteABCompareFileInfo(remoteInfo, _remoteABInfoDic);
        updateInfoCallBack("远端对比文件解析完成");

        GetLocalABCompareFileInfo((isOver2) =>
        {
            if (isOver2)
            {
                updateInfoCallBack("本地对比文件加载成功");
                // 3，对比它们，进行 AB 包下载（第三版已补上，见《资源更新删除》）
            }
            else
            {
                updateInfoCallBack("本地对比文件加载失败");
                overCallBack(false);
            }
        });
    });
}
```

**为什么用两个回调而不是返回值**：整个过程跨多帧（异步 + 协程），一个 `return` 根本没法把"以后才有的结果"带回去。

流程：

```
                    ┌─ updateInfo("开始更新资源")
CheckUpdate ────────┤
                    └─ DownLoadCompareFile（最多重试 5 次）
                              │ 成功
                              ▼
              File.ReadAllText(ABCompareInfo_TMP.txt)
                              │
                              ▼
              GetRemoteABCompareFileInfo → _remoteABInfoDic
                              │
                              ▼
              GetLocalABCompareFileInfo（协程）
                              │ 成功
                              ▼
              _localABInfoDic → 对比 → 删除 → DownLoadABFile
```

> 第三版已经补上了这一段：对比、删除、下载、写回对比文件，全部成功后调用 `overCallBack(true)`，详见《资源更新删除》。

### 3. DownLoadCompareFile：下到临时文件 + 失败重试

```csharp
public async void DownLoadCompareFile(UnityAction<bool> overCallback = null)
{
    print(Application.persistentDataPath);
    int reDownLoadNum = 5;                                  // 重试次数
    bool isOver = false;
    string localPath = Application.persistentDataPath + "/"; // 先算好路径

    while (!isOver && reDownLoadNum > 0)
    {
        await Task.Run(() =>
        {
            // 方法 1：远端对比文件下成临时文件
            isOver = DownLoadFile("ABCompareInfo.txt", localPath + "ABCompareInfo_TMP.txt");
        });
        reDownLoadNum--;
    }

    overCallback?.Invoke(isOver);   // 参数表示是否下载成功
}
```

| 点 | 说明 |
|----|------|
| `async void` | Unity 回调里写异步方法的常见写法：调用方 `await` 不了它，异常也不会抛给调用方（会变成未处理异常）。想被 `await` 就应该返回 `Task` |
| `Task.Run` | `FtpWebRequest` 是同步阻塞 API，放主线程会卡画面（弱网尤其明显），所以丢到线程池 |
| `print(...)` 的位置 | 在 `await` 之前，仍在主线程，合法。**`Task.Run` 内部不能碰 Unity 的大多数组件 API**（`transform`、`Instantiate`、`StartCoroutine`…），所以 `localPath` 要在外面先算好。`Debug.Log`/`print` 是少数线程安全的例外（`DownLoadFile` 的 `catch` 里就在后台线程调了 `print`） |
| 闭包 | `isOver`、`localPath` 被 lambda 捕获：lambda 里赋值，外面读结果 |
| 重试 | `while (!isOver && reDownLoadNum > 0)`，失败一次 `reDownLoadNum--`，最多 5 次 |
| 每次重试都 `File.Create` | 会把上次失败留下的半截文件清空重建，不会拼出脏文件 |
| `overCallback?.Invoke` | `?.` 防空；`UnityAction` 是 Unity 版无返回值委托 |

> 补充：`await` 之后代码会回到主线程（Unity 的 `SynchronizationContext`），所以 `overCallback?.Invoke` 里可以安全操作 UI。

### 4. GetRemoteABCompareFileInfo：只解析，不碰 IO

```csharp
public void GetRemoteABCompareFileInfo(string compareInfo, Dictionary<string, ABInfo> abDic)
{
    string[] lines = compareInfo.Split('\n');        // 按行拆
    string[] infos = null;
    for (int i = 0; i < lines.Length; i++)
    {
        infos = lines[i].Split(' ');                 // 按空格拆成 名字 大小 MD5
        abDic.Add(infos[0], new ABInfo(infos[0], infos[1], infos[2]));
    }
}
```

三个设计点：

1. **参数是"字符串 + 字典"，不是文件路径**：谁读的文件谁负责，解析函数只管拆字符串。这样远端（读 TMP 文件）和本地（`UnityWebRequest` 读 StreamingAssets）能共用同一份解析代码 —— 事实上 `GetLocalABCompareFileInfo` 内部调的就是它。
2. **字典由调用方传**：写进 `_remoteABInfoDic` 还是 `_localABInfoDic` 由调用方决定。这就是字典要从一个拆成两个的原因。
3. **命名不准确**：方法叫 `GetRemote...`，本地也在用。更准确的名字是 `ParseABCompareInfo`。读代码时别被名字骗了。

数据流：

```
"lua 1024 abc...\nmodel 2048 def..."
        │ Split('\n')
        ▼
["lua 1024 abc...", "model 2048 def..."]
        │ Split(' ')
        ▼
["lua","1024","abc..."] → new ABInfo(...) → abDic["lua"] = ABInfo
```

### 5. 易错点

| 易错点 | 说明 |
|--------|------|
| 空行 | 对比文件末尾若多一个 `\n`，会拆出空行，`infos[1]` 直接越界。生成端已用 `Substring` 砍掉最后一个换行，但下载/编辑过的文件不一定，建议 `RemoveEmptyEntries` |
| `\r` | 如果文件是 Windows 换行（`\r\n`），`Split('\n')` 后每行末尾残留 `\r`，MD5 多一个字符 → **对比永远不相等**。稳妥写法：`Split(new[]{"\r\n","\n"}, StringSplitOptions.RemoveEmptyEntries)` |
| 重复 `Add` | `CheckUpdate` 调两次会 `ArgumentException`（key 已存在）。应先 `Clear()` 或用 `abDic[key] = info` |
| `long.Parse` | 大小字段解析失败会抛异常；文件被截断时尤其容易 |
| TMP 残留 | 下载失败时 TMP 可能是半截文件；只要 `isOver` 为 `false` 就不会读它，逻辑上安全，但下次启动前最好删掉 |
| `File.ReadAllText` 在主线程 | TMP 在 `persistentDataPath`，几 KB 文本问题不大，但要意识到这是同步 IO |
| `async void` 抛异常 | 没人接得住，只会进 Unity 的未处理异常日志。内部尽量用 `try/catch` |

## 获取本地对比文件信息

### 1. 一个功能，两个同名方法（重载）

| 方法 | 职责 |
|------|------|
| `public void GetLocalABCompareFileInfo(UnityAction<bool>)` | **找路径**：决定读哪个文件，然后启动协程 |
| `private IEnumerator GetLocalABCompareFileInfo(string, UnityAction<bool>)` | **真正读**：`UnityWebRequest` 读文件 → 解析 → 回调 |

`void` 版本不是迭代器，不能 `yield return`，所以只能"判断完路径后 `StartCoroutine`"，把读取放进 `IEnumerator` 版本。

### 2. 路径优先级

```csharp
public void GetLocalABCompareFileInfo(UnityAction<bool> overCallback = null)
{
    // ① 可读可写目录里有 → 说明之前更新过
    if (File.Exists(Application.persistentDataPath + "/ABCompareInfo.txt"))
        StartCoroutine(GetLocalABCompareFileInfo(Application.persistentDataPath + "/ABCompareInfo.txt", overCallback));

    // ② 没有 → 用随包发布的默认资源（第一次进游戏）
    else if (File.Exists(Application.streamingAssetsPath + "/ABCompareInfo.txt"))
        StartCoroutine(GetLocalABCompareFileInfo(Application.streamingAssetsPath + "/ABCompareInfo.txt", overCallback));

    // ③ 两处都没有 → 当成本地没有对比信息
    else
        overCallback?.Invoke(true);
}
```

| 情况 | 读哪里 | 含义 |
|------|--------|------|
| `persistentDataPath` 有 | 可读写目录 | 更新过，这是最新的本地版本 |
| 只有 `StreamingAssets` 有 | 包内默认资源 | 首次启动 |
| 两处都没有 | 不读 | 打包时没设置默认资源；本地字典为空，远端的包都会当新增下载 |

> 第 ③ 个分支传的是 `true` 不是 `false`：**"没有本地对比文件"不算失败**，是合法的首次启动状态。

### 3. 为什么不用 File.ReadAllText

Android 上 `Application.streamingAssetsPath` 指向 APK 里的 `assets`，路径形如：

```
jar:file:///data/app/xxx/base.apk!/assets
```

- `File.Exists` 返回 **false**（它不认识 `jar:` 协议）；
- `File.ReadAllText` 直接抛异常。

所以读 StreamingAssets 只能用 `UnityWebRequest`（Unity 内部能处理 `jar:` 路径）。而 `persistentDataPath` 两种方式都行 —— 为了**一套代码走两条路径**，这里统一用 `UnityWebRequest`。

> 这也是"默认资源"不能简单用 `File` 读的根因；将来要做物理转存，也必须 `UnityWebRequest` 读 bytes 再 `File.WriteAllBytes`。

### 4. 协程读取

```csharp
private IEnumerator GetLocalABCompareFileInfo(string filePath, UnityAction<bool> overCallback = null)
{
    UnityWebRequest req = UnityWebRequest.Get(filePath);
    yield return req.SendWebRequest();

    if (req.result != UnityWebRequest.Result.Success)
    {
        overCallback?.Invoke(false);
        yield break;                                  // 失败必须提前结束
    }

    GetRemoteABCompareFileInfo(req.downloadHandler.text, _localABInfoDic);
    overCallback?.Invoke(true);
}
```

| 点 | 说明 |
|----|------|
| `UnityWebRequest.Get` | 本地文件也走"网络请求"这套 API，统一处理 `file://`、`jar:` |
| `SendWebRequest()` | 老版本叫 `Send()`；`yield return` 等它读完 |
| `req.result` | 用 `UnityWebRequest.Result.Success` 判断（老版本是 `isNetworkError` / `isHttpError`） |
| `downloadHandler.text` | 直接把文件内容当字符串取出来，不用自己拼 `StreamReader` |
| `yield break` | 失败时**提前结束协程**，不执行后面的解析 |
| 回调 | 协程不能 `return` 值，也不能带 `ref/out` 参数，所以只能用 `UnityAction<bool>` |

### 5. 完整流程

```
GetLocalABCompareFileInfo(cb)
  ├─ persistentDataPath/ABCompareInfo.txt 存在？
  │     是 → StartCoroutine 读它 → 解析进 _localABInfoDic → cb(true)
  ├─ StreamingAssets/ABCompareInfo.txt 存在？
  │     是 → StartCoroutine 读它 → 解析进 _localABInfoDic → cb(true)
  └─ 都不存在 → cb(true)（本地为空）
        读失败 → cb(false)
```

### 6. 如果要"物理转存"该怎么做

本课没写，但可以这样扩展：

```csharp
IEnumerator CopyDefaultToPersistent(string fileName)
{
    string src = Application.streamingAssetsPath + "/" + fileName;
    string dst = Application.persistentDataPath + "/" + fileName;

    using (UnityWebRequest req = UnityWebRequest.Get(src))
    {
        yield return req.SendWebRequest();
        if (req.result == UnityWebRequest.Result.Success)
            File.WriteAllBytes(dst, req.downloadHandler.data);
    }
}
```

转存完，`GetLocalABCompareFileInfo` 就只需要看 `persistentDataPath` 了。但要额外处理：转存在哪一步做、失败了怎么重试、以及"怎么知道已经转存过"（通常用标记文件）。

### 7. 易错点

| 易错点 | 说明 |
|--------|------|
| 用 `File` 读 StreamingAssets | 编辑器/PC 上能跑，一到 Android 就失败，是最典型的"只在真机上炸"的坑 |
| 忘记 `yield break` | 请求失败后继续解析空文本，会拆出空行导致越界 |
| `req` 没 `Dispose` | 代码里没写 `using`，要等 GC；正式项目建议 `using` 或手动 `Dispose` |
| 重载混淆 | 两个同名方法，`StartCoroutine` 只能传 `IEnumerator` 版本，别把返回 `void` 的那个传进去 |
| 协程只能由 `MonoBehaviour` 启动 | `ABUpdateMgr` 继承 `MonoBehaviour` 才能 `StartCoroutine` |
| 回调嵌套过深 | `CheckUpdate → 下载 → 本地 → 对比` 已经三层，后面加下载进度会更乱，可考虑用 `async/await` 或事件重构 |

## 一句话总结

> **默认资源在 `StreamingAssets`（只读，Android 在 APK 内），热更新资源在 `persistentDataPath`；所以本地对比文件要按 `persistentDataPath → StreamingAssets` 的顺序找，且只能用 `UnityWebRequest` 读。远端对比文件绝不能直接覆盖本地 —— 先下到 `ABCompareInfo_TMP.txt`，解析进 `_remoteABInfoDic`，AB 包全部下载成功后再覆盖。整条链 `CheckUpdate → DownLoadCompareFile(重试) → GetRemoteABCompareFileInfo → GetLocalABCompareFileInfo(协程) → 对比/下载` 全用回调串起来，因为跨帧异步没法用返回值。**
