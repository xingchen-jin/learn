## 📌 知识点一：自动布局是什么

虽然 `RectTransform` 已经能方便地手动布局，但 UGUI 还提供了一批**自动布局组件**，可以自动设置 UI 控件的**位置和大小**。

| 组成 | 含义 | 本课对应对象 |
|------|------|--------------|
| 自动布局控制组件 | Unity 提供的、专门用于布局管理的"管理性质"组件 | Horizontal / Vertical / Grid Layout Group、Content Size Fitter、Aspect Ratio Fitter |
| 布局元素 | 具备布局属性、可参与布局计算的对象 | 所有带 `RectTransform` 的 UI 组件（Image、Text 等） |

> 💡 理解要点：控制组件不会凭空猜大小，它要**读取布局元素的六个布局属性**才能算出结果。这正是知识点二要讲的内容——它是一切布局组件的"底层数据"。

## 🧩 知识点二：布局元素的六大布局属性

参与自动布局的布局元素必须包含一组布局属性。在 Inspector 中勾选/双击组件底部的布局属性区域，可看到 **6 个参数**，它们就是自动布局时参与计算的核心数据。

| 属性 | 英文名 | 作用 |
|------|--------|------|
| 最小宽度 / 最小高度 | minWidth / minHeight | 布局时的"底线"，一般不小于此值 |
| 优选宽度 / 优选高度 | preferredWidth / preferredHeight | "理想尺寸"，空间充足时尽量满足 |
| 弹性宽度 / 弹性高度 | flexibleWidth / flexibleHeight | 有**额外空间**时按比例再扩展的权重 |

### 计算顺序（先小后大，逐级分配）

1. **先分配最小宽高**——保证底线；
2. **空间足够时，分配优选宽高**——满足理想尺寸；
3. **仍有额外空间时，用弹性宽高按比例扩展**——填充剩余。

> 📝 口诀：**最小保底 → 优选吃饱 → 弹性分剩饭**。

### 两种默认行为
- 普通 UI 元素（如 Image）的六个布局属性**默认为 0**；
- **Text 组件特殊**：会随输入内容自动改变优选宽/高（文字越多，preferred 越大）——这也是后面 Content Size Fitter 能"自适应文本"的根因。

> ⚠️ 严谨提示：官方文档在 min / preferred / flexible 之外，较新版本还支持 Layout Element 的 **maxWidth / maxHeight（最大宽高）** 上限。即"保底 / 理想 / 上限 / 弹性"四类约束，本笔记后续示例一并使用。

### 手动改属性：Layout Element 组件
一般情况下你**不需要**手动修改这些属性。若确有需求，可给对象添加 **Layout Element（布局元素）** 组件，手动覆盖六个（含最大）属性：
- 设最小宽高 = 100：父容器缩小时，子对象仍**保持 ≥100**，不会被压扁；
- 设最大宽高 = 200 且取消"控制子物体大小/强制扩展"：父容器变大时，子对象**最多扩到 200** 即停；
- 分别设 flexible = 0.2 / 0.3 / 0.5：额外空间按 **2:3:5** 比例分配。

> 💡 唐老师强调：Layout Element "了解即可"，实际开发中多数布局效果**不加它也能达到**，它的作用是真正参与计算、提供约束。

## ⚙️ 知识点三：水平 / 垂直布局组（Horizontal / Vertical Layout Group）

**作用**：把同一父对象下的子对象**并排（水平）**或**竖直**排列。两者参数完全一致，给父对象 Add Component 添加后，原本重叠的子对象会立刻被排开。

| 参数 | 含义 |
|------|------|
| Padding（Left / Right / Top / Bottom） | 子对象与父容器四条边的内边距，默认 0；特殊需求再调 |
| Spacing | 相邻子对象之间的像素间隔 |
| Child Alignment | 九宫格对齐，决定子对象未填满空间时的对齐基准（默认左上） |
| Control Child Size（Width / Height） | 是否由布局组统一控制子物体宽高；勾选后子物体随父物体缩放、不可单独改 |
| Use Child Scale | 布局计算时是否把子物体的 Scale（X/Y）纳入考虑（子物体一般不缩放，可不勾） |
| Child Force Expand（Width / Height） | 是否强制子物体扩展以填满额外可用空间 |

> 🔎 实验印证（贴合课程）：
> - 勾选 Control Child Size → 拖动父对象，子 Image 大小/位置随之变化并顶满；
> - 子物体最小宽高默认 0 时，取消相关勾选再缩小父容器，子物体可能直接变 **0×0 消失**；此时加 Layout Element 设最小 100，即可"保底不被压没"；
> - 垂直布局同理：把多个子物体（甚至空物体）挂到父对象下，加 Vertical Layout Group 即自动往下排，调 Spacing 控制挨着还是留缝。
>
> 💡 游戏开发不像做网页，子控件大小常**手动设好**，布局组的核心目的只是"按序排列"，下面这些缩放控制项可不勾选。

## 🧮 知识点四：网格布局组（Grid Layout Group）

**作用**：把子对象当成一个个**格子**，按网格排列大小与位置，自动换行/换列。常用于**背包、道具栏**。

| 参数 | 含义 |
|------|------|
| Padding | 与父容器边缘的偏移（如设 5，则距上/左各空 5 像素） |
| **Cell Size（X / Y）** | 每个格子的宽高，填多少则子物体矩形就是多少（如 50×50） |
| Spacing（X / Y） | 横向、纵向格子间距 |
| Start Corner | 第一个元素起点：左上 / 右上 / 左下 / 右下 |
| Start Axis | 排列主轴：Horizontal 先填满行再换行；Vertical 先填满列再换列 |
| Child Alignment | 格子的九宫格对齐（一般左上） |
| **Constraint** | 约束模式，决定行/列数如何确定 |

**Constraint（约束）三模式：**
- **Flexible（灵活）**：完全按父容器尺寸自动决定行列——容器大就多排，容器窄就提早换行；**背包最常用**（只控制父容器大小，格子增减自动重排）。
- **Fixed Column Count**：固定列数（如设 2 则永远两列，多了继续往后扩行）。
- **Fixed Row Count**：固定行数（如设 2 则永远两行）。

> 📝 口诀：**格子定大小，Constraint 定行列；灵活随容器，固定锁一维。**

## 📐 知识点五：内容大小适配器（Content Size Fitter）

**作用**：自动调整自身 `RectTransform` 的长宽，使其适应内容。**常用在 Text 上，或配合布局组一起用。**

| 参数 | 选项 | 含义 |
|------|------|------|
| **Horizontal Fit** | Unconstrained | 不根据布局元素伸展宽度 |
| | Min Size | 按布局元素的**最小宽度**伸展 |
| | Preferred Size | 按布局元素的**优选宽度**伸展 |
| **Vertical Fit** | Unconstrained / Min Size / Preferred Size | 同上，作用于高度 |

> 官方补充：较新版本还提供 **Clamped** 选项——把尺寸约束在最小与最大之间，但不主动驱动宽高。

### 典型应用
1. **Text 自适应**：Horizontal/Vertical Fit 选 **Preferred Size**，文本内容一变，尺寸实时跟着 preferred 宽高动态调整（若选 Min，则用默认的 0，会"看不见"）。
2. **配合 Grid / Horizontal Layout**：给布局容器加 Content Size Fitter，把对应方向设为 Preferred Size，容器会**随子项数量自动扩展**该方向的尺寸。

### 🏆 本课最实用场景：Scroll View 背包列表
> Scroll View 的 `Content` 大小原本要**手动设**，格子多时设小了根本拖不到底、看不到下面的内容。
>
> 解法：在 `Content` 上同时挂
> - **Grid Layout Group**：Cell Size 50×50、Spacing 5、Padding 5；
> - **Content Size Fitter**：Vertical Fit = **Preferred Size**。
>
> 运行后动态增删格子，`Content` 高度**自动调整**，无需写一行代码。这正是自动布局组件"处理面板逻辑、少写代码"的核心价值。

## 🖼️ 知识点六：宽高比适配器（Aspect Ratio Fitter）

**作用**：① 让布局元素按设定比例调整自身大小；② 让布局元素在父对象内根据父对象尺寸自适应，同时保持宽高比。**用得不多，了解即可。**

| 参数 | 含义 |
|------|------|
| **Aspect Mode（适配模式）** | 见下表五种 |
| Aspect Ratio | 宽高比数值 = 宽 ÷ 高 |

| Aspect Mode | 行为 | 副作用 |
|-------------|------|--------|
| None | 不调整 RectTransform 以适应宽高比 | — |
| Width Controls Height | 宽不变，按比例算高 | — |
| Height Controls Width | 高不变，按比例算宽 | — |
| **Fit In Parent** | 调整自身大小/位置/锚点，**完整显示**在父矩形内并保持比例 | 出现**黑边**（≈ Canvas Scaler 的 Expand） |
| **Envelope Parent** | 调整自身填满父矩形并保持比例 | 部分**被裁剪**（≈ Canvas Scaler 的 Shrink） |

> 🔗 关联记忆：Fit / Envelope 两种模式与 **Canvas Scaler** 的填充逻辑相似——前者"完整但有黑边"，后者"填满但可能裁边"。
>
> 💡 典型用途：**背景图**。一张大图要在不同分辨率上始终填满屏幕，多选用 Envelope Parent；要完整显示不裁切则用 Fit In Parent。前两种模式针对"自身尺寸"，后两种针对"父对象尺寸"。

## ⚖️ 六大知识点速查与选型

| 组件 | 解决什么 | 关键参数 | 典型场景 |
|------|----------|----------|----------|
| 布局属性（6 项） | 一切布局计算的数据底层 | min / preferred / flexible（+ max） | 理解即可，不常手改 |
| Layout Element | 手动覆盖某对象的布局约束 | 最小/最大/弹性 | 保底、限幅、按比例分空间 |
| Horizontal / Vertical Layout Group | 子物体横排 / 竖排 | Padding / Spacing / Child Alignment | 横向工具条、竖向菜单 |
| Grid Layout Group | 子物体排成网格 | Cell Size / Constraint | 背包、道具栏 |
| Content Size Fitter | 让自身尺寸跟随内容 | Horizontal/Vertical Fit | Text 自适应、Scroll View Content |
| Aspect Ratio Fitter | 保持宽高比 / 适配父级 | Aspect Mode / Aspect Ratio | 响应式背景图 |

> 🧠 **选型口诀**：横竖排队用 H/V；格子背包用 Grid；尺寸跟内容用 Size Fitter；保持比例用 Aspect Fitter；要保底限幅才上 Layout Element。

## 📝 复习卡片（速记）

- **本质**：自动布局 = 布局控制组件（算）＋ 布局元素（提供属性）。
- **六属性计算顺序**：最小保底 → 优选吃饱 → 弹性分剩余。
- **Layout Group 六参数**：Padding、Spacing、Child Alignment、Control Child Size、Use Child Scale、Child Force Expand。
- **Grid 三约束**：Flexible 随容器（背包首选）、Fixed Column 锁列、Fixed Row 锁行。
- **Content Size Fitter**：Text 选 Preferred Size；Scroll View 的 Content ＝ Grid ＋ Size Fitter（Vertical=Preferred）→ 动态格子自动撑高、免写代码。
- **Aspect Ratio Fitter**：Fit In Parent 完整显示有黑边；Envelope Parent 填满画面有裁剪（对应 Canvas Scaler Expand / Shrink）。
- **本课重点**：六大布局属性的"了解"＋ 知识点 3~6 四个组件的"会用、会选型"；难点在属性计算机制，落点在 Scroll View 自适应布局。
