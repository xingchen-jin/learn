## 一、优先级与总体策略

**核心目标**：完成一个**可玩、有战斗循环、有基础任务引导**的小型 TPS 场景。  
**MVP 范围**：武器系统 → 敌人 AI → 玩家信息与伤害 → 背包/物品 → 任务与 UI → 音效/音乐。  
**贯穿模块**：UI 框架、音效管理器、数据驱动结构（ScriptableObject）需在初期搭建，避免后期返工。

**建议**：网络通信暂缓，可在面试中说明未来规划；驾驶系统作为亮点口头描述，不实际开发。

## 三、贯穿模块的处理建议

- **UI 框架**：第一阶段就建立 UIManager 和事件系统，所有 UI 更新通过事件通知，避免直接引用。
    
- **音效管理器**：阶段一扩展音效池，后续直接按枚举播放，无需改动其他系统。
    
- **数据驱动**：所有可配置数据（武器、敌人、物品、任务）都用 ScriptableObject，便于编辑器调整和版本管理。
    

网络通信可以不做，但在代码中预留接口：将玩家输入封装为命令，未来可替换为网络同步。这样在面试中可以提及“架构支持网络扩展”。

## 五、Unity API 使用说明

以下是规划中涉及的关键 Unity API 汇总：

|API|传递参数|返回值|函数内部实现功能|性能开销|
|---|---|---|---|---|
|`ScriptableObject.CreateInstance<T>()`|无|T（派生类实例）|创建可序列化的数据资产，不依赖场景对象，用于配置数据。|仅在编辑器或运行时创建时产生内存分配，游戏运行中不频繁调用。|
|`Physics.Raycast(Vector3 origin, Vector3 direction, out RaycastHit hitInfo, float maxDistance, int layerMask)`|`origin`：射线起点；`direction`：射线方向；`hitInfo`：命中信息；`maxDistance`：最大距离；`layerMask`：层遮罩|`bool`|从起点发射射线，检测与指定层碰撞体相交，返回首个命中。|单次查询开销小，批量调用与射线数量线性相关，适合每帧使用。|
|`Animator.SetFloat(int id, float value, float dampTime, float deltaTime)`|`id`：参数 ID；`value`：目标值；`dampTime`：阻尼时间；`deltaTime`：时间增量|`void`|平滑设置浮点参数，用于动画混合。|每帧调用开销极小，内部进行插值计算。|
|`CharacterController.Move(Vector3 motion)`|`motion`：位移向量|`CollisionFlags`|移动角色，处理碰撞，不直接修改 Transform。|单次移动开销低，取决于碰撞体复杂度。|
|`ObjectPool<T>.Get()`|无|T（池中对象）|从对象池获取实例，若池空则创建。|O(1) 操作，无 GC 压力。|
|`ObjectPool<T>.Release(T obj)`|`obj`：要归还的对象|`void`|将对象归还池中，若池满则销毁。|O(1) 操作，无 GC 压力。|
|`AudioSource.PlayOneShot(AudioClip clip, float volumeScale)`|`clip`：音频片段；`volumeScale`：音量缩放|`void`|播放一次性音效，不中断当前音频。|每次调用分配临时音源，频繁调用会有 GC，建议使用音源池。|
|`UIElements.EditorWindow.CreateGUI()`|无|`void`|编辑器窗口创建 UI 树，用于自定义编辑器工具。|仅在编辑器窗口打开时调用，不影响游戏性能。|
|`JsonUtility.ToJson(object obj)`|`obj`：要序列化的对象|`string`|将对象序列化为 JSON 字符串。|序列化时产生字符串分配，频率低可接受。|
|`NavMeshAgent.SetDestination(Vector3 target)`|`target`：目标位置|`bool`|设置导航目标，自动计算路径。|计算路径可能产生少量开销，但每帧调用亦可接受。|
