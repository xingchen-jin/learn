## 1. 巡逻行走动画传不过去 — 已修

根因在 [EnemyBase.cs:115](vscode-webview://0nctrrvovg30s4msoemv0gjbthpulef03uaoleph37falit13no3/Assets/Scripts/NPC/EnemyBase.cs#L115)：`Animator.SetFloat(hash, value, dampTime, deltaTime)` 是**阻尼版**，它只把参数朝目标值挪一小段，必须**每帧调用**才会收敛。而 `SetWalking()` 只在 `SetNewTargetPoint()` 里调用一次，参数从 0 只能爬到 0.2 左右，混合树永远够不到 1.5 的行走阈值 → 看起来就是"传不过去"。

改法（不动物理、不动 UI，只改 NPC 自己这一层）：

- `SetIdle/SetWalking/SetRunning/SetMoveSpeed` 现在只记录**目标速度**，由 `EnemyBase.Update()` 用 `Mathf.SmoothDamp` 每帧平滑写入 Animator（[EnemyBase.cs:50](vscode-webview://0nctrrvovg30s4msoemv0gjbthpulef03uaoleph37falit13no3/Assets/Scripts/NPC/EnemyBase.cs#L50)）。
- 公开 API 签名一个没变，`Partol`/`ChaseTarget` 照旧调用，其他模块零影响。
- 顺手删掉了 `SetIdle/SetWalking` 里的 `Debug.Log`（每次切换刷屏），并在 `Init()` 取不到数据时 `return`，避免下面空引用。

顺带修了一个隐藏的不一致：`Init()` 会用数据库数据**整个替换** `enemyData`，但行为树的 `AttackRange` 只在 `Awake` 写过一次，于是行为树用 2.23、`ChaseTarget` 用 0.5。现在初始化后会再同步一次（[EnemyBase.cs:186](vscode-webview://0nctrrvovg30s4msoemv0gjbthpulef03uaoleph37falit13no3/Assets/Scripts/NPC/EnemyBase.cs#L186)）。

## 2. 深渊怪物的行为树 — 找到两个真凶

我把场景里那份 17 节点的树从预制体覆盖数据里解码出来了：

```
Repeater → Selector
  ├ Sequence [CanSeeTarget] → Selector
  │    ├ Sequence [距离≤AttackRange] → Crossfade("Attack")
  │    └ Sequence [Crossfade("Locomotion") → ChaseTarget]
  └ Sequence [Crossfade("Locomotion") → Partol]
```

**(a) 追不到目标**：`CanSeeTarget` 里 `target` 那个变量引用在图中是**空的**（节点数据里连名字都没有），它只是节点私有变量；而 `ChaseTarget` 和距离判断读的是共享变量 `TargetPlayer`，**没有任何节点往它写过** → 永远是 null → `ChaseTarget` 每帧返回 Failure → 选择器每帧掉回巡逻分支。

**(b) 跳闪**：因为 `Sequence` 失败后下一帧会从**第一个子节点**重新执行，而 `ChaseTarget` 每帧失败，于是 `Crossfade("Locomotion")` 被**每帧重新触发一次** → Locomotion 状态每帧重新开始 → 模型抖动/闪。而且这个动画控制器的 Attack/Locomotion **没有任何 Transition**，全靠脚本 CrossFade，所以刷得特别明显。

代码侧修复（都在 BTExtension 自己的节点里，没碰别的模块）：

- [CanSeeTarget.cs](vscode-webview://0nctrrvovg30s4msoemv0gjbthpulef03uaoleph37falit13no3/Assets/Scripts/NPC/AI/BTExtension/Conditionals/CanSeeTarget.cs)：除了写自己的变量，再按名字把目标写回行为树共享变量（变量名做成 Inspector 字段，默认 `TargetPlayer`）。`SetVariableValue<T>(PropertyName, T)` 这个重载我是从 DLL 元数据里核对过的，`EnemyBase` 已经在用同一套 API。
- [ChaseTarget.cs](vscode-webview://0nctrrvovg30s4msoemv0gjbthpulef03uaoleph37falit13no3/Assets/Scripts/NPC/AI/BTExtension/Actions/ChaseTarget.cs)：目标取不到时**退回 `NPCPerception.DetectedPlayer`**（图里没连好也能追）；每帧重新取目标；`SetDestination` 暂时失败返回 Running 而不是 Failure（否则会来回切分支抖动）；新增 `stoppingDistanceScale`（默认 0.8）让停止距离**落在攻击范围之内**，避免贴着判定边界停导致分支反复切换。
- [Partol.cs](vscode-webview://0nctrrvovg30s4msoemv0gjbthpulef03uaoleph37falit13no3/Assets/Scripts/NPC/AI/BTExtension/Actions/Partol.cs)：`EnemyData` 为空时用默认速度，不再空引用。

**需要你在编辑器里做的三件事**（图数据是二进制块，我手改风险太高）：

1. 把攻击分支里的 `Crossfade("Attack")` 换成你已经写好的 **`PlayAttackAnimation`** —— 它会等动画播完再返回，天然带滞回，闪的问题就没了。
2. 那个 **`SetParameters(MoveSpeed)` 节点是游离的**（没有父节点），而且它的下标 16 超出了 `m_TaskData.Array.size = 16`，加载时会被丢掉；同理节点 14/15 那条 `IsGameObjectVaild` 支线也没接上。请删掉或接好。
3. 整棵树现在是**场景实例上一份 3.6 万行的覆盖差异**，底下压着预制体里 9/9 那棵只有 4 个节点、`Sequence` 全是空的旧树。建议在预制体上 Apply 一次，让树回到预制体里。

另外：`attackRange` 运行时以**数据库**为准（预制体 Inspector 里那个 2.23 会被 `Init()` 覆盖成 0.5），要哪个值请改 `NPC_Database_SO.asset`。还有 `NPCPerception.Update` 每帧 `Debug.Log`，上次运行刷了 4.1 万行、日志 82MB，建议挂到已有的 `showDebug` 开关上。

## 3. "平行节点传 agent 速度" 方案 — 合理，有个前提

方向是对的，而且正好能治上面那个 flicker：**`SetParameters` 这类赋值节点是幂等的，每帧重复执行无所谓；`Crossfade` 不是**，重复执行就会每帧重启状态。所以：

- 可以放在 `Parallel` 复合节点里，也可以直接作为 `Sequence` 的第一个子节点（`Sequence` 每次从头执行时会顺带重跑它，这正是你要的效果）。
- **前提是别再用 `Crossfade("Locomotion")` 去切移动状态**：Locomotion 已经是默认状态且没有 Transition，MoveSpeed 驱动混合树就够了，两套混用会互相打架。
- 数据源建议直接读 `NavMeshAgent.velocity.magnitude` 或 `desiredVelocity`，而不是 `agent.speed`（`speed` 只是设定值，停止/转向时不会归零，脚会一直滑）。
- 阈值要归一：现在 `walkSpeed/runSpeed` 都是 2.5，而混合树阈值是 0 / 1.5 / 3.5，所以 2.5 会落在走跑之间。要么把 agent 速度映射到 0~3.5 再传，要么把阈值对齐。

我已经把 `SetMoveSpeed(float)` 留成"设置目标速度"的入口，你后面直接从这个节点调它就行，不用再改 `EnemyBase`。

Unity 下次获得焦点会自动重新编译，编译完先看 `CanSeeTarget` 能不能正常往 `TargetPlayer` 写值（运行时选中怪物看行为树变量面板），再试追击。
